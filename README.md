## 先用最简单的话解释

原方法每一步决定“每个像素的红、绿、蓝数值分别增加或减少多少”。本方案每一步决定“几种横向、纵向明暗变化模式分别加强或减弱多少”，再把这些模式叠加到源图上。

模式系数由模型梯度决定，不是随便给图片加条纹。目标仍然是让向量朝目标图移动。先限制搜索的频率范围，可能让搜索更集中，但也可能删掉有用方向，因此必须实验检验。

## 保持不变的范围

- 选图规则与当前参考项目的实际代码一致；第一轮直接使用已经冻结的十组图像，不能为频域方法单独挑更容易的目标图。
- 保持三个攻击代理编码器、主评估编码器、原图尺寸和像素扰动上限一致。
- 首轮只做选图、图像扰动、向量评估，不增加长期记忆系统、多轮问答、生成模型或付费接口。
- 原项目主评估使用 CLIP-B-32（采用三十二像素图块的基础版图文对比编码器），新方案也首先使用它。其他已有适配的编码器只作为可选扩展，不默认全部运行。

优先争取两条路线中的一条：同样设备、同样时间下向量接近程度更好；或达到近似效果时耗时更短。显存降低另行实测，不能用“参数少了”代替硬件证据。具体阈值与测量口径见实验协议。

实现已经完成“兼容检查 → 公平像素基线 → 固定频带方法 → 单组轻量验证”。若以后继续研究，应先决定是否追加短程实验；没有小实验信号前，不开展大规模参数搜索。

## 已实现的四种运行方法

- `legacy_pixel`：参考像素实现，用三个代理的联合计算图，并在每步重新聚类目标局部特征；只用于核对数学兼容性。
- `fair_pixel`：公平像素基线，启用目标缓存和逐代理梯度，作为正式性能对照。
- `frequency`：固定频带的 DCT(离散余弦变换)紧凑系数方法。
- `progressive_frequency`：按预设时间比例逐步扩频的候选方法；默认关闭，只有修改配置显式启用后才能运行。
- `zero`：不更新图片的零步完整流水线对照。

生成和主评估严格分开。生成阶段只加载三个攻击代理；评估阶段重新读取已保存的 PNG(便携式网络图形)图片，再加载主评估器。每次运行保存配置、模型与权重指纹、实现代码内容标识、冻结样本、失败原因、时间、显存、检查点、最终图片、四类向量和汇总指标；汇总前还会复核关键产物摘要与跨方法条件一致性。
